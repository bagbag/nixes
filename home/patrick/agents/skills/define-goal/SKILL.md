# Define Goal

Own the user-facing alignment that must precede architecture and planning. The
goal belongs to the user; this skill helps make it explicit, testable, and
small enough to guide the next coherent milestone.

## Choose the mode

- **Establish** — define a new project or substantial arc.
- **Advance** — turn a ratified direction into the next milestone or wave.
- **Refocus** — recover when implementation, reviews, or accumulated scope have
  drifted from the purpose.

## Build the contract

Orient cheaply from the user's framing and current project owners before asking
questions. Produce one compact contract covering:

- intended user and defining outcome;
- problem or burden being reduced;
- defining value path and any load-bearing hypothesis;
- next observable milestone and why it matters;
- smallest coherent walking skeleton needed to prove it;
- explicit non-goals and safe deferrals;
- constraints and quality criterion;
- acceptance evidence; and
- unresolved empirical assumptions with the cheapest useful test.

Resolve factual uncertainty before presenting choices. Bring genuine
consequential alternatives to the user with honest trade-offs and a marked
recommendation. Do not design architecture while the goal is still ambiguous.

## Challenge the milestone

Ask: if this milestone succeeds, what has been delivered or learned about the
reason the work exists?

A safe fallback, no-op, placeholder, or universally fail-closed path may be
valuable infrastructure evidence, but it is not product-milestone acceptance
when it bypasses the defining value path. Keep acceptance open and name the
missing contract, input, capability, or empirical validation instead of
silently redefining success.

If structural scope or process keeps growing without advancing executable value,
step back to Refocus mode and derive a smaller coherent milestone. Do not solve
goal drift by adding another gate or document.

## Ratify and record

Present the contract for user ratification. Once ratified, update the current
board's goal and next action. Promote only enduring product conclusions into an
existing durable owner; do not create a parallel goal document by default.
Architecture and planning consume the ratified contract afterward.
