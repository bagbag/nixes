## Asking the user

- Open each question with the problem in one plain sentence and two or three
  realistic consumer scenarios, including the simple case. Give every option
  for, against and footguns. Name items in plain words; put ids in brackets.
- Ask for wanted behavior and features first, with short examples of each
  option's observable result. Infer the mechanism and actions from the answers
  and present them for one confirmation; write or act on them only after it.
  Ask a mechanism question only where the confirmed behavior leaves several
  clean mechanisms.
- Build each round around its highest-[Priority](../shared/work-tracking.md#priority)
  unblocked question. Add questions sharing its premise or root cause, or the
  consumer concept or flow it shapes; leave other same-module questions for
  their own round. Split along premises above about six questions.
- When the user flags one instance, find all of its kind, including earlier
  rulings, and show the list before asking about scope.
- Walk through each round in chat first, readable without arc context: items
  and ids in brackets, the answered question (and the posed one if different),
  one line per decision-protocol step and every choice. Define each term, tool
  feature or earlier artifact an option relies on in one clause at first use
  (what it is, where it runs); drop arguments that do not apply to the case.
  Make contested choices questions.
- Before the walkthrough, re-screen your own rulings under decision-protocol
  Options; classify sequencing and process choices as the worker's call.
- Disclose your own rulings in that walkthrough, before asking: entailed
  decisions, defect-fix behaviors, dropped or narrowed parts, framing choices
  (excluded options, accepted premises, question bundling). Give each its
  strongest realistic alternative, the cleanliness test, principle or
  correctness property that alternative fails, and evidence (`path:line`,
  probe, ruling id); scale from one line to a mini decision packet by stakes.
  Ask about any ruling you cannot ground.
- Repeat the list, with later rulings, in each release or ratification
  request.
- End the walkthrough with an offer to ask. Once the user accepts, ask with
  the structured-question tool using your own option labels: adopt the end
  state, then one question per contested choice, no cap per round
  (four per call; continue in further calls). Mark the recommendation strong
  or lean; include disagreements and footguns.
- For changed consumer use, show the recommendation's short consumer example in
  chat and every realistic option's example in its preview. Derive process
  questions from the root fix.
- Step up an abstraction level when all options feel wrong.
- When the user answers with a criterion instead of an option, rerun the
  decision protocol from Top-down before asking again.
- When the user declines a question to clarify, ask what they want clarified,
  answer, and ask again; confirm answers given inside the declined round. After
  two declines, re-check the premise.
